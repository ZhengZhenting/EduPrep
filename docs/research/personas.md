# 用户画像 (Personas)

> **状态**: Draft (P6 用户研究 · 轻量版)
> **更新**: 2026-06-23
> **方法说明**: 本轮为**轻量版画像**，基于对"在德国的国际学生"群体的领域理解构建，用于驱动产品功能设计。真实访谈与可用性验证安排在 P9（详见 [roadmap](../roadmap/eduprep_roadmap.html)）。

EduPrep 的目标用户是**在德国高校就读、母语非德语的国际学生**。下面三个画像覆盖了从语言挣扎到效率优化的不同梯度。

---

## Persona 1 — Anna｜本科交换生（语言挣扎型）

| 维度 | 描述 |
|---|---|
| **背景** | 大二交换生，中国来德，专业课为德语授课 |
| **德语水平** | B1（够日常，不够学术） |
| **设备/习惯** | 笔记本 + 平板，课后看讲义 PDF |
| **核心目标** | 看懂德语讲义、跟上课程进度、通过期末 |
| **主要痛点** | ① 德语学术术语看不懂，查词典逐个翻太慢；② 不确定一章的重点是什么；③ 听课跟不上，课后靠 PDF 自学 |
| **现在怎么解决** | DeepL 整页翻译（丢失结构）+ 手动记词 |
| **对 EduPrep 的期待** | 双语摘要 + 术语对照 + 一眼看清结构 |
| **命中功能** | Preview（双语摘要、词汇、结构图）、术语图谱节点 |

---

## Persona 2 — Wei｜硕士研究生（跨材料整合型）

| 维度 | 描述 |
|---|---|
| **背景** | 硕士在读，英语授课项目，但参考资料/课件大量是德语 |
| **德语水平** | A2–B1（专业英语强，德语弱） |
| **设备/习惯** | 一学期累积大量 PDF，跨多门课 |
| **核心目标** | 把一学期零散材料整合成可复习的知识体系、抓住考试重点 |
| **主要痛点** | ① 同一概念散落在多份 PDF，串不起来；② 不知道概念之间的先后依赖；③ 考前不知道自己哪里弱、该重点复习什么 |
| **现在怎么解决** | Notion 手动整理 + 自制 Anki 卡，耗时巨大 |
| **对 EduPrep 的期待** | 跨材料的概念关联、知道自己的薄弱点、有人帮安排复习 |
| **命中功能** | 课程级知识图谱、掌握度热力图、GraphRAG 跨 PDF 检索、自适应出题 |

---

## Persona 3 — Sofia｜效率优化型学生（时间紧张型）

| 维度 | 描述 |
|---|---|
| **背景** | 高年级本科，德语 B2+，同时打工，时间碎片化 |
| **德语水平** | B2（语言基本不是障碍） |
| **设备/习惯** | 手机/平板碎片时间学习，重视效率 |
| **核心目标** | 用最少时间达到最好复习效果、不重复学已掌握的内容 |
| **主要痛点** | ① 学完就忘，不知道什么时候该复习；② 时间有限，不想在已会的内容上浪费；③ 缺乏对"还剩多少没掌握"的整体感 |
| **现在怎么解决** | 凭感觉复习，临考突击 |
| **对 EduPrep 的期待** | 按遗忘曲线提醒复习、只考没掌握的、进度可视化 |
| **命中功能** | FSRS 间隔重复调度、自适应出题、掌握度进度可视化 |

---

## 画像如何驱动功能

三个画像构成一条**从"看懂"到"整合"到"高效"的能力阶梯**，正好对应 EduPrep 从现有功能到 roadmap 功能的演进：

- **Anna（看懂）** → 现有 Preview/Learn 已基本覆盖；
- **Wei（整合）** → 由 P7/P8 的知识图谱 + GraphRAG 解决；
- **Sofia（高效）** → 由 P9 的学习科学引擎（知识追踪 + FSRS）解决。

> 这说明 roadmap 的功能不是堆砌，而是沿着真实用户的能力需求阶梯逐层展开。详见 [痛点→功能映射表](./pain-points-to-features.md)。
